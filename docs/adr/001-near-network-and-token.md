# ADR 001: NEAR network, accounts and test token

- **Status:** Accepted for the hackathon MVP
- **Date:** 2026-11-14

## Decision

GlobalPay's NEAR MVP uses the NEAR network identifier `testnet` and the public RPC
`https://rpc.testnet.near.org`. NEAR account IDs and base58 transaction hashes are used directly;
there is no numeric EVM chain ID.

The MVP token is the live NEP-141 contract `usdc.fakes.testnet`. Its on-chain `ft_metadata` response
was verified as:

```json
{
  "spec": "ft-1.0.0",
  "name": "Bridged USDC",
  "symbol": "USDC.e",
  "decimals": 6
}
```

The account name makes its purpose explicit: this is a permissionless **testnet asset**, not
production Circle USDC. UI and documentation must call it `USDC.e test asset` or equivalent.

The token exports `ft_transfer_call`, the NEP-145 storage methods and a permissionless testnet
`mint(account_id, amount)`. Unrelated accounts have finalized successful mint transactions. The
storage registration amount returned by `storage_balance_bounds` is 0.00125 NEAR.

Accounts:

| Role | Account ID |
|---|---|
| Deployer / receipt prototype | `globalpay-receipts.testnet` |
| Internal-wallet demo account | `demo.globalpay-receipts.testnet` |
| Escrow contract | `vault.globalpay-receipts.testnet` |

Keys generated by near-cli were written directly to its secure keychain. No private key is stored in
the repository. The Flutter Ed25519 key is a separate key encrypted by Android Keystore and must be
added to the demo account by public key before it can transact.

The complete manifest is `deployments/near-testnet.json`.

## Consequences

- Every balance and amount uses metadata decimals, never an assumed 18 decimals.
- Account provisioning and NEP-141 storage registration are separate required operations.
- Mainnet and production stablecoins are outside this MVP.
- Existing EVM configuration remains intact and is not reused by NEAR.
